First-run Review Profile: a prototype

Throwaway prototype for issue #12. The file, its libraries and the answers are made up. Nothing here is saved anywhere.

The question: when a review runs and there's no Review Profile, what should the conversation that creates one ask, in what order, and with what defaults? Is it quick for a designer, and does it produce a profile complete enough for each Review Skill? Pick how the review was started, then step through the conversation.     Questions this prototype raises
    
    
      
      
    1. Compact or step by step? Compare walkthroughs 1 and 2. Compact asks fewer questions, but tucks the accessibility target into a list of defaults.
      2. 
      
    2. Should "Not now" exist? It lets accessibility run on WCAG 2.2 AA defaults without saving anything. Is that a helpful escape, or a way to never set a profile up?
      3. 
      
    3. Where does the pointer to a profile live in a Figma file? This prototype writes a one-line "Review Profile" page. Shared plugin data on the file is another option, but people can't see it.
      4. 
      
    4. Is a private custom skill a real team option? Only its creator can use it until it's shared with the org, and whether the agent can share it is untested.
      5. 
      
    5. Who owns each layer? The file can't tell, so owners start as "unknown". Findings blamed on a layer then name nobody. Should first run insist on an owner for each layer?
      6. 
      
    6. Should a skill run on its own set up only its own section? See walkthrough 5. The Orchestrator later runs only what the profile covers, so a profile first made by the accessibility skill never gets the other reviews until someone adds them.
      7. 
      
    7. Should the Report Writer write the profile? The profile is read by agents, and the report by people. The text here is written plainly for an agent.
